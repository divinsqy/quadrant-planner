# v1 Local-first Sync, Conflict Resolution, Backup, and Restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add optional Supabase synchronization without compromising local-first behavior, explicit field conflicts, secure credentials, soft-delete propagation, and independent full backup/restore.

**Architecture:** Every local mutation commits to Drift and appends an outbox operation in the same transaction. Sync pushes idempotent operations, pulls cursor-based changes, merges non-overlapping field edits, and records same-field conflicts for user resolution. Backup is separate from sync and excludes credentials.

**Tech Stack:** Drift, HTTP/Supabase REST/RPC, flutter_secure_storage, archive/ZIP-compatible container if needed.

**Spec:** `docs/superpowers/specs/2026-09-30-quadrant-planner-v1-design.md`

## Global Constraints

- App is fully usable without login/network.
- Local commit happens before network.
- Tokens only in OS secure storage.
- Same-field conflicts are never silently overwritten.
- Soft deletion uses `deletedAt`; default trash retention 30 days.
- Backup must not include access/refresh tokens.
- Restore creates a pre-restore snapshot first.

## Review Focus

1. Process/network failure after local commit but before upload must leave a retryable outbox item.
2. Replaying the same outbox operation must be idempotent.
3. Delete from one device followed by stale offline edit from another must not resurrect the task silently.
4. Same-field conflict must survive app restart until resolved.
5. Restore of a corrupt/incompatible backup must leave the current database untouched and keep the pre-restore snapshot.
