# Plan 06：同步、备份与恢复

实现基于批准的 `2026-09-30-v1-06-sync-backup.md`，仅在 `v1-rewrite`，未推送或合并。

## 功能

- SQLite 事务触发器覆盖所有用户数据表。未登录时完整使用本地功能；已登录时本地提交同时写入 outbox，网络由后台协调器单独处理。
- 冻结已尝试操作的 ID 和内容，支持断网重试、重启恢复、分页拉取、字段三方合并。不同字段自动合并，同字段进入持久化冲突中心；文本可保留任一版本或手工合并。
- OS 安全存储保存 access/refresh session，支持邮箱 OTP、刷新和退出。日志与持久化错误只保留诊断代码，不保存原始响应或凭据。
- 持久 tombstone 保护删除；离线旧编辑不会静默恢复任务。回收站提供明确恢复操作，至少保留30天；有待同步操作、未决冲突或未确认的云删除时不清理。
- 设置页提供同步中心、冲突中心、回收站、`.qpb` 备份/恢复、JSON 和 CSV 导出；工作区页头显示同步状态。
- `.qpb` 包含任务/子任务/依赖/标签、项目/里程碑/不可变历史、活动、日程/锁定计划/Focus、周报/笔记/样式、设置和迁移来源。恢复前先生成快照，再校验格式、版本、哈希、数量和引用关系；替换在一个 Drift 事务中完成。恢复后云同步暂停，需明确重新开启。
- JSON 为 schema-versioned 用户数据；CSV 包含项目、标签、删除标记并保留中文/RTL/UVM/AXI/dmac_* 文本。原有周报 Markdown/XLSX/纯文本导出继续使用 Plan 05 实现。
- schema v5 增加同步控制、shadow、操作元数据、tombstone/恢复意图及里程碑历史的跨设备唯一 ID；保留 v1–v4 升级路径。

## 实现裁定

1. 使用事务触发器覆盖写入，而非逐个仓库添加钩子，防止设置、关系和日历替换漏入队；以后改变表结构需要同步迁移捕获规则。
2. 使用逻辑 ZIP 与事务导入，保持 Drift 连接及订阅；跨 schema 恢复需要显式格式迁移。
3. 工作区绑定首次登录账户，退出保留队列；切换账户需独立工作区，避免账户间数据混入。
4. 保留有调用者的 v0 同步代码，新 v1 app 使用独立 RPC；兼容层清理留给 Plan 07。
5. 真实 Supabase migration/RLS/OTP 与原生安全存储须在配置后的环境验收；本地操作及已测适配边界独立可用，云端启用仍需真实联调。
6. 安装器、签名和公证验收由 Plan 07 负责；本次仅补齐必要 entitlement，发行前仍需平台烟雾测试。

## 独立审查与修复

完成一次全分支、独立上下文的只读审查。审查提出6个实质问题，全部接受并在一次修复阶段完成；没有延期的次要问题。

- 冲突发生后再次编辑，保留本地会覆盖为旧值：解析时读取最新本地值，冲突页随本地编辑刷新。
- 缺少父记录而延迟应用远端数据时，本地新编辑可能上传尚未应用的旧字段：持久化应用前基线，待应用实体暂缓上传。
- 延迟应用成功后，本地合并字段没有重新入队：统一应用完成流程，保留并上传合并结果。
- 先解决删除再解决文本冲突会丢失恢复意图：恢复意图持久化到服务器确认，最终操作明确携带恢复标记。
- 独立有效的日历或计划块变更合并后可能重叠：应用前检查聚合约束，将冲突放入冲突中心，锁定块原位保留。
- 关闭应用时，未完成网络请求仍访问已关闭数据库：销毁后停止处理迟到结果，并覆盖启动期间关闭的生命周期边界。

上述问题有7个失败后通过的回归测试，另增启动期间关闭测试，亦确认失败后通过。最终全量测试覆盖所有修复。
